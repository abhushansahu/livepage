Reading the long thing

The part that stops you is rarely the writing. It is not knowing where the argument is, or whether you got there.

⌥A Marked before you start

An agent reads the article and marks only the passages worth stopping at, in the same six colours. There is no target count — the prompt says so, because asking a model for five gets you five whether or not a fifth exists. An article that makes no point worth marking gets nothing, and says so.

Every quote is checked against the article before it becomes a mark. A paraphrase or an invention is thrown away rather than painted somewhere approximate.

The shape down the edge

Every marked passage as a tick at its own depth, your own highlights solid and an agent’s suggestions hollow, with how far you actually read shaded behind them. Click a tick to jump. It is the scrollbar an IDE gives you, for an argument instead of a file.

⌥J and ⌥K move between marks without touching the mouse.

⌥S Terms explained in place

Words an article leans on get a quiet underline; hover for what it means here, ⌘-click to jump to where it was defined. Answers are cached per page, so the second hover is instant. Noisy on a site you read daily — ⌥S turns it off for that site and leaves it alone everywhere else.

Thinking on it

Built as a layer over the Chrome you already live in. Nothing is stored just because you opened a tab.

On the page

Select a span. Six highlight colours and a comment. Notes sit in a reserved right margin, aligned to the quote — Google Docs / Notion style, not a floating overlay.

Threads can fork

Any message can branch. You and an agent can take different readings of the same span without overwriting each other. Ask Cursor or Claude Code; they get a parsed packet, not a second copy of the page.

When the page changes underneath

A highlight is a quote, so a rewritten page can leave it with nowhere to sit — and it would take a whole conversation with it. Those collect in a dock instead of vanishing, with the saved copy of the text around them, and re-attach to the passage where it lives now.

Scroll is the truth

Reading status is how far you actually got, not a clip checkbox. Opening a page and leaving leaves no trace. LivePage writes a record the first time you keep it: highlight, comment, star, list, tag, or import.

Find the sentence, not the article

Search returns the passage you marked and the thread on it, with the match shown in place — not a page card you then have to read again to find the line. Open the page and it scrolls to it.

Dashboard of open loops

Untouched Watch Later, X bookmarks, Reddit saves, RSS, half-read pages, and comments still waiting keep coming back. Hide rooms that get loud. Variant A is feed-first; B starts in lists.

This Chrome’s sessions

Harvest X bookmarks, Reddit saved, and YouTube Watch Later from the profile you already signed into. No second login. Feeds can be added from a page that advertises RSS, or from Settings.

Obsidian / git vault

Bind a vault folder. Write vault dumps ordinary markdown plus catalog.json. GitHub is the sync bus between machines. Chrome cannot push for you.

Install

Load unpacked into the Chrome you already use. Homebrew cannot inject an extension into that profile.

  1. Clone the repo, then open chrome://extensions, enable Developer mode, and Load unpacked → select the extension/ folder. Pin LivePage.
  2. Browse as usual. ⌥H highlights a selection, ⌥M comments, ⌥A has an agent mark up the article, ⌥⇧L opens the dashboard. Clicking the LivePage icon shows what is on for the page in front of you, with the key for each.
  3. For in-thread agent replies, keep npm run agent-host running in the repo. The host binds loopback only and pairs with this extension — web pages cannot invoke it. No cloud API keys.

Limits, honestly

This is an extension, not a research browser. It cannot rewrite navigation the way Horse Trails does.

Highlights use text-quote selectors. A page that rewrites the paragraph can still leave one with nowhere to sit — it collects in a dock with its thread intact rather than disappearing, and you re-attach it by selecting the passage where it lives now. Infinite-scroll feeds snapshot themselves when you highlight, so the anchor has somewhere to live.

The extension runs on every http(s) page because the product is “think on the live web.” Harvest uses the cookies of this Chrome profile. If you are not logged into X here, LivePage cannot invent that session.

Agent replies stay on your machine. Marking up an article shells out to the Cursor or Claude Code CLI already installed there, so it costs a real call and waits to be asked rather than running on every page you open. If the host is down, LivePage says so, and you still have the packet to paste a reply back by hand.

No PDFs yet. LivePage works on http and https pages; a bundled viewer that would give PDFs the same margin is planned, not built. There is also no backup or restore yet — the vault dump is one-way, so a wiped Chrome profile takes your highlights with it.
